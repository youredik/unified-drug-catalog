# unified-drug-catalog — единый каталог лекарств

Проектная память. Читается агентом первым делом; здесь то, что нельзя вывести из кода.

## Что это

Сервис принимает данные о лекарствах и товарах аптечного ассортимента от нескольких
аптечных сетей, приводит к единой модели, объединяет дубликаты, сохраняет сведения
обо всех источниках, отдаёт каталог в JSON и содержит способ проверки корректности.

Работающая реализация, а не описание подхода: конвейер отрабатывает целиком.

**Границы предметной области.** Витрины, фронтенда, цен, остатков и операции удаления
здесь нет и не должно быть. Если в коде всплывает `Offer` с ценой, подавление вместо
DELETE или поиск как продуктовая функция — это выход за границы проекта, убирать.

**Данные вымышленные, и это обязательное условие.** Публичный репозиторий не должен
содержать ни чужих файлов, ни реальных торговых марок с приписанными им синтетическими
кодами. Наименования и производители выдуманы, штрихкоды — из служебного диапазона GS1
`2xx`. Реальные факты (SmPC, статья 27.1, режим МДЛП) допустимы только как ЦИТИРУЕМАЯ
мотивировка в документации, а не как содержимое данных.

## Проверенные факты, на которых стоят решения

Всё ниже проверено инструментом или первоисточником. Не переспорить без новой проверки.

| Факт | Как проверен |
|---|---|
| Реализация MOD-10 верна | скриптом, с контролем на заведомо валидных штрихкодах `5901234123457`, `4006381333931`, `0012345678905` |
| Префикс GS1 `2xx` — restricted distribution, реальным розничным товарам не выдаётся: годится для синтетических штрихкодов | спецификация GS1 |
| `UK` — не валидный ISO 3166-1 alpha-2, канонический `GB` | ISO 3166 |
| Более подробный источник бывает неверен ровно в том поле, где выглядит убедительнее: на реальном препарате вторичные источники давали плёночную оболочку, SmPC — сахарную | SmPC держателя РУ |
| «Film-coated» у источника C лежит в **торговом наименовании**, а не в структурном поле (`pack.kind: "tabs"`) | чтением данных |
| Взаимозаменяемость ЛП — ст. 27.1 закона об обращении ЛС, перечень формирует НЦЭСМП внутри одного МНН | КонсультантПлюс, regmed.ru |
| ЕСКЛП вводит «потребительскую единицу» для дозировок через концентрацию (мг/мл, МЕ/мл, %) | паспорт ЕСКЛП, приложение Г |
| МДЛП: с 01.03.2026 разрешительный режим — касса блокирует продажу при отрицательном ответе | отраслевые источники 2026 |
| Правила и LLM ошибаются комплементарно: правила переобъединяют | OpenSanctions Pairs, arXiv 2603.11051 |
| У `fast-xml-parser` актуальная CVE-2026-26278 на расширение сущностей | Snyk |
| Allowlist по хосту обходится подменой DNS | CVE-2026-54353 |
| У образа `postgres:18` том монтируется в `/var/lib/postgresql`, а НЕ в `.../data` | контейнер падал на старте, пока не исправили |
| pg-boss 12 не заводит очереди сам: без `createQueue` джоба уходит в никуда | чтением `.d.ts` и живым прогоном |
| TypeScript 7.0.2 проект собирает и типы проходят, НО `typescript-eslint` его не поддерживает: `Error: typescript-eslint does not support TS 7.0` | поставил, прогнал, откатил |
| Карантин `minimumReleaseAge` может блокировать ИСПРАВЛЕНИЕ уязвимости: патч свежее 7 суток не ставится | столкнулись на `brace-expansion@5.0.8` (вышел за 5 дней до) |

## Инварианты архитектуры

Проверяются `pnpm arch` (dependency-cruiser), все правила на `error`. Гейт проверен
намеренным нарушением — он ловит.

```
domain  ←  normalize  ←  match  ←  connectors  ←  pipeline  ←  cli
   ↑ стрелки только внутрь                          ↑
                                                    db
```

- `domain` не импортирует ничего из проекта. Это Published Language.
- `normalize` и `match` — **чистые функции без I/O**. Ни файлов, ни сети, ни БД.
  Именно это делает возможными property-тесты.
- `connectors` не знает про матчинг. `adjudicator` — адаптер, не знает про приём и хранение.
- `db` — только схема, подключение и миграции. Порт хранилища живёт в `pipeline`,
  потому что порт принадлежит тому, кто им пользуется, а не тому, кто его реализует.
- Параметры-свойства в конструкторах запрещены (`erasableSyntaxOnly`): они эмитят
  рантайм-код и ломают нативный стриппинг типов в Node.
- **Детерминированность — инвариант, а не пожелание.** Время и `runId` приходят
  параметрами сверху; кластеры сортируются по НАИМЕНЬШЕМУ идентификатору участника,
  а не по первому попавшемуся (иначе порядок позиций зависит от порядка чтения —
  это поймал property-тест). На этом стоят golden-снапшот и `catalog:diff`.

## Ключевые решения и почему

1. **Невалидный GTIN не отбрасывает запись.** «Проверить и отбросить» уничтожило бы
   весь датасет. Идентификатор понижается в роли: валидный — основание утверждать
   тождество, невалидный — только основание сравнить.
2. **Флаг качества входит в математику, а не в лог.** У идентификатора в
   `comparison.ts` разные уровни `equal_and_valid` (u = 0.00001) и `equal_but_invalid`
   (u = 0.002).
3. **Провенанс и выживание — по полям, а не по записи.** Источник C самый точный
   по производителю и неверный по лекформе. Глобальный рейтинг источников неверен
   по построению.
4. **Побеждает ПРОВЕРЯЕМАЯ специфичность.** Уточнение без подтверждения справочником —
   конфликт, а не победа. Именно поэтому `Film-coated` не вытесняет `Tablet`.
5. **Формат даты объявлен в манифесте, не угадан.** `03.04.2023` неразрешима.
6. **Рецептурность tri-state**, `unknown` никогда не схлопывается в `otc`.
7. **ИИ в основном пути НЕ участвует** — см. следующий раздел.

## Про ИИ: решение и обоснование

**Языковая модель здесь не нужна.** Конвейер работает без неё: `NoopAdjudicator` стоит
по умолчанию, конвейер отрабатывает целиком.

Замер на размеченном наборе (12 пар, `pnpm eval`):

```
базовая линия   precision 1.000   recall 1.000   F1 1.000   неопределённых 4
зазор между классами 0.70 в log2 (множитель 1.62)
```

Правила не ошибаются. Модель купила бы только разбор 4 спорных пар, которые иначе
уходят человеку. Ради этого платить деньгами, задержкой, недетерминированностью
и поверхностью для инъекции — плохая сделка. **Модель проверена и осознанно
не включена.**

Что при этом остаётся в репозитории и почему это и есть ИИ-инженерная часть:
набор трудных случаев (`ground-truth.ts`), свип по порогам и `measureContribution` —
функция, гоняющая одно и то же с моделью и без. Адаптер `ClaudeAdjudicator` написан
и выключен.

Когда включать: если серая зона перестанет помещаться в ручной разбор, или если
рост числа источников схлопнет зазор между классами.

## Команды

```bash
pnpm ingest      # приём, нормализация, объединение, сохранение прогона
pnpm export      # → catalog.json, детерминированный
pnpm report      # отчёт качества
pnpm explain <id># разбор позиции: провенанс и веса сравнений
pnpm catalog:diff# что изменилось между прогонами

pnpm test        # юнит-тесты (без Docker)
pnpm lint        # линтер с проверкой типов
pnpm test:integration  # живой PostgreSQL через Testcontainers
pnpm arch        # архитектурные гейты
pnpm typecheck

docker compose up -d --wait && pnpm db:migrate   # база
pnpm worker      # обработчик очереди pg-boss
pnpm ingest --store=postgres --enqueue           # задача уходит воркеру

pnpm eval        # замер вклада арбитра (без ключа честно скажет, что замер не проводился)
pnpm eval:record # живой прогон модели, пишет вердикты в fixtures/ (нужен ANTHROPIC_API_KEY)
```

`UPDATE_GOLDEN=1 pnpm test` — обновить эталон каталога. Только осознанно.

## Как добавить источник

Манифест в `packages/connectors/src/sources.ts`, ACL в `acl/`, точка входа в реестр —
и зелёный conformance-набор (9 проверок). Ни строчки в ядре.

## Как добавить хранилище

Реализовать `CatalogStore` из `packages/pipeline/src/ports.ts`. Их три: память,
файлы, PostgreSQL. Интеграционный тест утверждает, что каталог от выбора не зависит, —
если новое хранилище это нарушит, тест упадёт.

## Состояние

**Готово целиком.** Приём трёх форматов, нормализация, объединение
с провенансом по полям, `catalog.json`, отчёт качества, разбор решения, диф версий,
PostgreSQL со слоями bronze/silver/gold/audit, воркеры pg-boss с транзакционным
outbox, Docker Compose.

149 юнит-тестов и 7 интеграционных, 8 пакетов под гейтом, типы и линтер чистые,
CI на GitHub Actions. Демо-набор: 6 записей трёх сетей → 3 позиции каталога.

Не сделано осознанно: полные справочники EDQM/ATC/МНН (подмножество с точкой
расширения), обогащение по внешним реестрам, LSH/MinHash (резерв за десятками
миллионов), OpenTelemetry.

## Чего не делать

- Не возвращать витрину, цены, остатки и операцию удаления — они вне границ проекта.
- Не «чинить» контрольную цифру до правильной. Оригинал и канон хранятся рядом.
- Не схлопывать `unknown` в `otc`.
- Не назначать победителем непроверяемое уточнение.
- Не включать модель в основной путь без нового замера, который покажет пользу.
- Не брать время и случайность внутри конвейера — только параметром сверху.
- Не обновлять golden-снапшот, чтобы «починить» упавший тест, не разобравшись,
  что именно изменилось в выгрузке.
- Не вносить в репозиторий реальные торговые марки, производителей, регистрационные
  номера и чужие файлы данных. См. раздел про вымышленность данных выше.
- Не подкручивать пороги матчинга, чтобы сошёлся тест. Если метрика поехала —
  сперва понять, какая фикстура изменила смысл. Однажды переименование бренда
  превратило опечатку `Nurofeen` (удвоенная гласная) в `Acmefleks` (другое
  искажение), и зазор между классами ушёл в минус; чинить надо было фикстуру.
- Не понижать `--audit-level` и не выключать карантин пакетов ради зелёного CI.
  Исключение записывается поимённо, с путём достижимости и сроком снятия —
  см. `auditConfig` в `pnpm-workspace.yaml`.
- Не приводить недоверенное значение к тексту через `String(x)`: на объекте это
  даёт «[object Object]», которое едет дальше как данные. Есть `asText`
  и `describeValue` в `packages/normalize/src/scalar.ts`.
